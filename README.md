# SolarReport

Программа на C# переносит измерения солнечной панели из текстового файла в XLS и считает параметры по листу «С=0.7» исходной книги

## Запуск

Скачайте архив Windows из [Releases](https://github.com/Arsenyrud/solar-report/releases), распакуйте его в обычную папку с правом записи

1. Замените `inputs/measurements.txt` своими измерениями
2. Запустите `SolarReport.exe`
3. Введите площадь панели в см² и нажмите «Сформировать отчет»
4. Откройте `reports/result.xls`

Для следующего измерения замените содержимое того же текстового файла и снова нажмите кнопку расчета

Excel и отдельная установка .NET для запуска не нужны, среда выполнения включена в exe. Программа рассчитана на Windows 10/11 x64

Площадь можно вводить с точкой или запятой. После успешного расчета она сохраняется в `area.txt` рядом с программой

## Входной файл

Три столбца: напряжение в вольтах, ток в амперах, время в секундах

```text
[0, 0, 0]
Voltage_1 (1)  Current_1 (1)  Time Ch_1 (1)
-0.050022840499878  -0.0077575095929205  0.061708
-0.042733669281006  -0.007755087222904   0.108348
```

Строка `[0, 0, 0]` и заголовок LabTracer пропускаются. Чистый файл без заголовка тоже подходит

Разделитель столбцов: табуляция, пробел или точка с запятой. Десятичный разделитель: точка или запятая. Поддерживается научная запись вроде `-2.5e-3`

Пустые строки и строки с `#` пропускаются. Остальные поврежденные строки останавливают расчет с указанием номера строки, предыдущий отчет сохраняется

Полярность тока берется из шаблона: при генерации ток отрицательный, плотность тока считается как `-I/S`

## Что сохраняется в отчете

Встроенный шаблон соответствует книге «1686-1 Кр16 1 склейка ВАХ.xls» из задания

Программа обновляет лист «С=0.7», сохраняет остальные листы книги, размеры строк и столбцов, оформление и четыре диаграммы. Отчет открывается на обновленном листе

Количество точек берется из входного файла. Диапазоны формул и диаграмм обновляются вместе с данными, старые точки в конце удаляются

Метод расчета и соответствие ячейкам описаны в [docs/calculations.md](docs/calculations.md)

## Темновые данные и Sinton

В исходном шаблоне есть темновая кривая в T:U, но нет измерений Sinton в K:L. При обычном запуске используется темновая кривая из шаблона, а результаты Sinton помечаются «нет данных»

Темновая кривая должна относиться к той же панели, что и световая. В приложенном примере они не совпадают, поэтому расчет дает отрицательные сопротивления. Программа сообщает об этом и сохраняет полученные значения

Для замены темновых данных укажите `DarkInputPath` в `settings.json`. Для Sinton укажите `SintonInputPath`. В обоих файлах нужны напряжение в вольтах и ток в амперах, третий столбец времени допустим

Площадь для темновой кривой берется из того же поля площади, H1 и V2 обновляются вместе

Параметр JEQE в H4 по умолчанию остается равным `0.038 А/см²`, как в шаблоне. Если для панели измерен другой JEQE, задайте `ReferenceCurrentDensity`

```json
{
  "InputPath": "inputs/measurements.txt",
  "OutputPath": "reports/result.xls",
  "TemplatePath": null,
  "ReferenceCurrentDensity": 0.038,
  "DarkInputPath": "inputs/dark.txt",
  "SintonInputPath": null
}
```

Относительные пути в настройках отсчитываются от папки программы. `TemplatePath` позволяет использовать свою копию исходной книги с листом «С=0.7» и тем же расположением ячеек

## Сборка из исходников

Нужен [.NET SDK 10.0.402](https://dotnet.microsoft.com/download/dotnet/10.0), версия зафиксирована в global.json

```bash
git clone https://github.com/Arsenyrud/solar-report.git
cd solar-report
dotnet restore SolarReport.slnx --locked-mode
dotnet test tests/SolarReport.Tests/SolarReport.Tests.csproj -c Release --no-restore
dotnet build SolarReport.slnx -c Release --no-restore
```

На Windows архив с автономной программой собирается одной командой

```powershell
./scripts/publish.ps1
```

Архив появится в `artifacts/SolarReport-win-x64.zip`

## Командная строка

Есть отдельная версия для проверок и запуска на Linux, она использует тот же расчет и тот же экспорт

```bash
dotnet run --project src/SolarReport.Cli -c Release -- \
  --area 2.341 \
  --input examples/measurements.txt \
  --output artifacts/example.xls
```

Список параметров: `--help`. Пути, переданные параметрами командной строки, отсчитываются от текущей папки

На Linux полный цикл проверки выполняет `bash scripts/verify.sh`. В GitHub Actions выполняются тесты и сборка Windows-архива

Проверенный пример: Jsc `3.307661565 мА/см²`, Voc `1.363483836 В`, FF `59.50208083%`, эффективность `30.82944766%` при площади `2.341 см²` и JEQE `0.038 А/см²`

Готовый пример отчета находится в `examples/result.xls`

Результаты проверки описаны в [docs/verification.md](docs/verification.md)

Исходные материалы и их контрольные суммы указаны в [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)
